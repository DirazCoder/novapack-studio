NovaByte Studio

        
Everything you need to build, package, and ship a `.novaapp`.

      

      

        

          
          
          
          
          
          
        

        


          

            
Getting started

            
NovaByte Studio is a desktop IDE for creating, building, and packaging .novaapp applications for NovaByte OS and compatible NBOSP systems. You get a GUI for everything — no CLI required.

            
    
              
  1. Create a project from a template — blank, webapp, browser, utility, game, dashboard, form, markdown-viewer, or chat.
    2. 
              
  2. Edit your code in the built-in CodeMirror 6 editor — multi-tab, syntax highlighting, TypeScript intellisense, and a live HTML preview pane.
    3. 
              
  3. Fill in your manifest (name, id, permissions, window size) in the Manifest tab.
    4. 
              
  4. Build from the Build tab — this validates your manifest, bundles every file, and writes a .novaapp to your output directory.
    5. 
              
  5. Inspect any .novaapp by dragging it into the Package Inspector to check its manifest, files, and signature.
    6. 
            

            
⚠️ Reference external scripts such as app.js instead of putting code in an inline script block. The host defers packaged entry-page scripts until HTML parsing is complete, so DOM-ready wrappers are not needed. See the FAQ for details.

          


          

            
Manifest format

            
Every app needs a manifest.json at its root. Required fields:

            

              
FieldDescription

              
idUnique app ID, reverse-domain format (e.g. com.example.app)

              
nameDisplay name shown in the OS

              
versionSemantic version x.y.z

              
entryMain HTML file to load

            

            
Common optional fields: description, author, icon, permissions, optionalPermissions, defaultSize, minSize/maxSize, resizable, frame, categories.

            
App IDs must be lowercase reverse-domain (io.github.you.app) — MyApp or myapp with no dot will fail validation at Build time. Web-app shortcuts use the webapp_ prefix instead.

          


          

            
Permissions

            
Permissions gate what your app can access on the host OS. Declare required permissions in permissions; missing sensitive grants may be requested at launch, but denial does not block the app. Optional sensitive permissions are not prompted at launch and can be requested at runtime or granted from Settings → Apps. Low-risk permissions are auto-granted when declared unless previously denied.

            

              
CategoryPermissionsRisk range

              
Filesystemvfs:access, vfs:read, vfs:write, vfs:delete, vfs:metadataLow – Critical

              
Networknet:internal, net:external, net:websocketLow – High

              
Clipboardclipboard:read, clipboard:writeLow – High

              
Mailmail:read, mail:write, mail:send, mail:deleteHigh – Critical

              
Calendarcalendar:read, calendar:write, calendar:deleteMedium – High

              
Contactscontacts:read, contacts:write, contacts:deleteMedium – High

              
Devicedevice:notifications, device:geolocation, device:camera, device:microphoneLow – Critical

              
Systemsystem:info, system:settings, system:apps, system:app-launch, system:events, system:root, system:background, system:background:live, system:autostartLow – Critical

              
Adminadmin:apps, admin:users, admin:system, admin:auditHigh – Critical

              
Sandboxsandbox:nested-webview, sandbox:same-origin, sandbox:escape-popupsHigh – Critical

            

            
Hover any permission in the Permissions tab (or in the manifest editor) for its exact risk level and description.

            
admin:* permissions also require the machine itself to be in Admin Access mode (Settings → Privacy & Security) — granting the permission alone isn't enough. mail:* always acts on whichever account the user has connected via the Email app; there's no way to supply separate credentials.

          


          

            
Building

            
Hitting Build validates your manifest and permissions, Base64-encodes every project file, generates a signature over the payload, and writes <app.id>.novaapp to your output directory.

Frequently asked questions


            
My app won't install / gets flagged on install — why?

            
An inline <script> block with real code in index.html is blocked by the install-time content scanner. Put the code in a sibling file and reference it instead:

            
<script src="app.js" defer></script>

            
For packaged apps, the host defers external entry-page scripts until HTML parsing is complete, so code in app.js can access elements declared in the page without a DOMContentLoaded wrapper. Keep defer to preserve the same behavior when testing outside NovaByte OS. Dynamically created scripts and documents keep normal browser timing.


            
Where do I put third-party libraries?

            
Drop single minified files (JS/CSS) into the vendor/ folder in your project — they're bundled automatically at Build time. Reference them as <script src="vendor/yourlib.min.js" defer></script>. Don't copy entire node_modules folders in.


            
My manifest permission isn't doing anything?

            
Studio lists all 40 supported permissions in the Permissions section of this Help window. Some permissions also need a matching manifest flag: sandbox:nested-webview needs "allowNestedWebview": true, sandbox:same-origin needs "sandbox": { "allowSameOrigin": true }, and sandbox:escape-popups needs "allowPopupsToEscapeSandbox": true. Both the permission and its flag are required. Low-risk permissions are auto-granted when declared unless previously denied; denial of any permission does not block app launch.


            
Still stuck?

            
Open the Command Palette (Ctrl+Shift+P) and search for an action by name, or consult NOVAAPP.md in the Studio repository for the complete manifest, permission, and IPC API reference.
